# 陆运距离与参考时效

2026-10-22 用户澄清：只需大概道路路径，使用普通驾车版本，无需货车专用接口。入口为左侧「方案工作台」下方的一级菜单「陆运距离与时效」。

## 数据源与配置

- 中国大陆境内：高德普通驾车路径规划 2.0，使用 Web 服务 Key，另调用官方坐标转换将 GeoNames WGS84 坐标转换后算路。无需申请物流货车基础版或高级版。
- 美国和欧洲：HERE Routing API v8，使用 `transportMode=car`；以账户权限和实际地区覆盖为准。
- 全球地名库不等于全球道路覆盖。未预设地区及中国跨境路线提示按口岸分段核实；无可用路线或服务失败时不提供直线距离替代值。
- 高德：`https://restapi.amap.com/v5/direction/driving`，策略 32（推荐），请求 cost/navi 以取得耗时及路段信息，默认 `ferry=1` 避让轮渡。HERE 同时请求避让轮渡和车辆摆渡列车，并验证响应。

官方资料：[高德普通驾车接口](https://lbs.amap.com/api/webservice/guide/api/newroute)、[坐标转换](https://lbs.amap.com/api/webservice/guide/api/convert)、[HERE Routing](https://docs.here.com/routing/docs/routing-v8-intro)。

本机执行 `npm run road:configure`，先输入服务序号 1（高德）、2（HERE）或 3（两者），出现密钥提示后再输入 Key。隐藏输入不显示字符；脚本写入被 git 忽略的本机 `.env`，保留其他配置，不打印密钥。

配置变量：`AMAP_WEB_SERVICE_KEY`、`HERE_ROUTING_KEY`。兼容已保存的旧变量 `AMAP_TRUCK_KEY`，不需要用户重新填写，接口仍为普通驾车。Docker Compose 同样传递上述配置；不将密钥打入镜像或浏览器代码。Key 和安全密钥不应粘贴到聊天、代码、截图或 GitHub。

## 查询与显示

只需选择起运国家、城市、目的国家、城市，即可查询；城市需从列表选择，按稳定 ID 与国家校验。普通路线不使用车辆尺寸、重量、轴数或车牌参数，页面移除相关输入。旧客户端的车辆字段继续兼容，但不参与路由和数据库匹配。

结果包括推荐普通驾车路线的公路里程、全程里程、地图驾车耗时、卡车参考驾驶耗时、单驾和双驾参考时效；高德结果另显示主要途经道路摘要。城市参考点测算不等于具体仓库间里程，主要道路摘要不代表完整导航指示。

所有结果明确标注：普通驾车参考路线不校验货车限高、限重、限行、危险品和超限大件通行条件。货物类型不阻止查看大概路线；实际适运条件仍由业务确认。多式联运方案引擎中的特殊货物承运校验保持独立。

## 时效口径

- 参考平均车速默认 60 km/h，可在 10—100 范围调整；这是业务测算参数，不是法定限速。
- 每个公路段的卡车参考驾驶耗时取「地图驾车耗时」与「里程 ÷ 参考平均车速」中的较大值，避免直接将小客车耗时当成卡车运输时效，也不将已知拥堵耗时算短。
- 默认单驾每天累计驾驶 8 小时、双驾 16 小时。从开始行驶计，每个 24 小时周期先驾驶最多设定小时数，其余休息。提前到达不追加休息。
- 例如 1800 km、地图耗时 18 小时、参考车速 60 km/h：卡车参考驾驶耗时 30 小时，单驾参考 78 小时，双驾参考 38 小时，未含手动附加耗时。
- 装卸、等待、通关及边境等待初始为空（未计入），可明确填写 0。已填值单独累加，不抵扣休息或摆渡耗时。
- 可选出发时间按设备时区输入，仅推算参考到达时间，结果按北京时间显示；路线使用原查询时的数据，不预测未来路况。
- 默认关闭轮渡和车辆摆渡列车；开启后拆分非公路里程与耗时，不把摆渡当成驾驶。接口返回违反避让的路线或未知关键警告时拒绝使用。
- 这是粗略业务估算，不代表司机排班合规计算或送达承诺；道路交通和作业变化会改变实际时效。

## 数据库优先

成功且通过校验的原始普通驾车路线自动保存到业务数据库 `road_routes`，长期保留，重启后继续使用。查询首先读取数据库，命中后不调用路线或坐标转换 API；即使移除服务 Key，也能读取已有记录。失败和无路线不入库，落库失败明确提示。

匹配依据：普通驾车版本标记、数据源、起止国家与城市 ID、方向、参考坐标和摆渡选择。车速、驾驶窗口、装卸、等待、通关及出发时间不影响路线复用，而是按本次输入重新计算参考时效。旧货车版记录保留，按不同版本标记隔离，避免混用。

界面区分「API 查询（已保存数据库）」与「数据库记录（本次未调用 API）」，显示带年份的原查询时间，并提示历史数据不代表实时路况。不会自动到期重查；损坏记录会提示维护，避免静默重复计费。旧 `ROAD_CACHE_TTL_SECONDS` 设置已不再生效。

同一进程的相同条件并发查询会合并；不同进程首次同时查询仍可能分别调用服务商。仅保存路线参数、路段、道路摘要、服务提示和取得时间，不保存 Key。

## 接口与验证

`GET /api/road/status` 返回服务配置状态，不返回密钥；`POST /api/road/query` 执行查询与复用。沿用登录会话和同来源校验，每分钟最多 20 次查询、同一实例最多 4 个外部请求，单次 12 秒总超时。供应商 URL 固定，不接收任意代理地址，不输出带 Key 的 URL 或原始错误信息。

自动化检查覆盖普通驾车参数、坐标及单位、时效边界、车辆字段不参与普通路线、车速重算但不重查、重开数据库复用、路线条件隔离、并发合并、失败不入库、关键警告、摆渡拆分、登录保护及界面流程。SQLite 本地验证，PostgreSQL 由 CI 验证；实时联调结果单独报告。
