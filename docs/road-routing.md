# 陆运距离与卡车时效

2026-10-22 用户确认开发：中国国内查询为主，美国与欧洲为辅。入口为「方案工作台 → 陆运距离与时效」，独立于供应商资源与多式联运方案计算。选择起运国家、城市、目的国家、城市即可发起查询；城市必须从候选列表选择，按稳定地名 ID 和国家校验。

## 数据源和开通

| 区域 | 预设数据源 | 服务要求 |
| --- | --- | --- |
| 中国大陆境内 | 高德物流 API · 货车路径规划高级版 | Web 服务 Key、物流货车付费服务权限、坐标转换权限 |
| 美国境内 | HERE Routing API v8 · Truck | 项目 API Key、货车路由服务权限和相应套餐 |
| 欧洲境内及欧洲国家之间 | HERE Routing API v8 · Truck | 同上，以实时路线响应和当地覆盖为准 |

全球地名库不等于全球货车道路覆盖。中国至欧洲等跨区域、香港、澳门及其他未预设地区会明确提示需要按口岸分段核实。没有路线、岛屿连接需要摆渡、城市参考点无法匹配道路、供应商异常或权限未开通时，不返回推测的直线里程。

### 本机安全配置

在项目目录执行：

```powershell
npm run road:configure
```

按提示选择高德、HERE 或两者，以隐藏输入方式粘贴自己的 Key。脚本只修改被 `.gitignore` 排除的本机 `.env` 对应字段，保留其他配置，不输出密钥。随后重启 IMT，进入查询区实际查询。状态中的「已配置」仅表示已设置 Key，实际权限和账户额度通过首次查询验证。

Windows 脚本使用系统 PowerShell；其他部署环境可直接将密钥写入服务端环境变量。不要复制密钥到聊天、浏览器代码、仓库、截图或工单日志。

```dotenv
AMAP_TRUCK_KEY=your-private-web-service-key
HERE_ROUTING_KEY=your-private-project-api-key
ROAD_CACHE_TTL_SECONDS=0
```

Docker Compose 已传递上述变量；在部署服务器的私有 `.env` 中设置后重建应用容器即可。密钥不打包进容器镜像、不设置为 Vite 变量，CI 的单元和浏览器测试不需要真实付费 Key。

## 车辆及通行限制

预置两个可修改的业务测算模板，均默认「尚未确认」：

| 模板 | 长 / 宽 / 高 m | 实际车货总重 t | 核定总质量 t | 核定载重 t | 轴数 / 国内分类 |
| --- | --- | --- | --- | --- | --- |
| 普通重型货车 | 9.6 / 2.5 / 3.8 | 18 | 25 | 15 | 3 / 重型 |
| 轻型货车 | 5.9 / 2.2 / 3 | 3.5 | 4.49 | 2 | 2 / 轻型 |

模板是初步测算值，不对应用户真实车辆，不保证任何地区的合法装载能力。请按整车含货物的最大外廓和真实车辆质量修改；修改任何参数后清除「已确认」，再次确认后才按已确认参数展示。货物重量不能代替车货总重，核定载重也不能代替实际货重。

高德使用 `size`、`length`、`width`、`height`、`load`（核定总质量，吨）、`weight`（核定载重，吨）、`axis`；高级版显式传入车长并请求 `avoid_ferry` 避让轮渡、不放宽限重；实际总重不作为独立参数传入，结果明确提示。可选省份简称与车牌号码须同时填写；不填时，接口不按车牌核查政策限行。GeoNames 的 WGS84 坐标先经高德官方坐标转换服务转换，再查询货车路线。

HERE 显式传入整车长度、宽度、高度（厘米）与实际 / 核定总重（千克）；轴荷、特殊许可、排放区等仍需核实。所有关键警告及限行违反结果均拒绝使用，包含供应商以后新增的未知 critical 警告。高德限行结果为起点、途径或终点受限时拒绝使用。不会降级到小汽车路线。

危险品、超限大件可以在界面标明，但本查询会说明需要专项核实，不生成普通货车结果。多式联运资源中的特殊货物承运校验保持独立。

## 距离与时效

- 公路里程：货车推荐路线中公路路段的里程，非最短路径承诺；全程里程另计摆渡距离。
- 驾驶耗时：接口返回公路路段预计耗时；包括该数据源计入的道路通行影响，不含本系统添加的驾驶休息。
- 单驾 / 双驾：默认每日累计驾驶 8 / 16 小时，均可修改；从开始行驶计，每个 24 小时周期先驾驶最多 N 小时，其余休息。提前到达不追加休息。
- 例：纯驾驶 18 小时，无额外耗时，单驾 8 h/日测算为 50 小时，双驾 16 h/日测算为 26 小时。不会简单用 `18 / 8 × 24` 计算，也不把 3 小时短途膨胀为一天。
- 装卸、等待、通关及边境等待：初始为空（未计入），允许明确填写 0；已填值单独累加，不抵扣休息或摆渡时间。
- 出发时间：可选，用设备当地时区输入，以明确的 UTC 时间传输；只用于时效加法推算到达时间，结果按北京时间显示。路线仍按查询时的数据计算，不承诺指定未来日期的路况与限行预测。
- 默认禁止轮渡和车辆摆渡列车。HERE 同时请求避让并验证响应，避免服务商返回违反避让的路线；高德请求避让轮渡并检查完整步骤中的轮渡和列车指示。允许后单独展示非公路路段，计入全程但不计为驾驶。摆渡耗时推进累计时钟，不视为驾驶；班次、可载车型及额外排队待确认。高德依赖步骤文字识别，遇到标记不完整的上游数据仍需人工复核。
- 单驾 / 双驾为业务测算，不是各地区驾驶法规、调度执行或送达保证。城市参考点测算不等于具体仓库门到门里程。加入司机休息以后可能改变实际到达某路段的时段限制，正式执行需重新核实。

修改任何查询条件立即清除之前结果；等待中的旧响应不能覆盖新的条件。查询结果保留当次输入、数据源、查询时间、车辆参数、计算假设和未计入事项，不回写供应商线路或历史方案。

## API 与运行边界

- `GET /api/road/status`：数据源名称、区域、密钥是否配置及开通链接，不返回密钥。
- `POST /api/road/query`：国家与城市 ID、车辆参数、计时假设和摆渡开关。生产环境沿用登录会话及同来源校验，每分钟最多 20 次请求；服务同时最多处理 4 个对外查询。
- 每次查询共用 12 秒对外超时，国内转换和路由共享这段时间；失败不自动重试计费请求。
- 默认不缓存供应商结果。获得供应商临时存储许可后，设置 `ROAD_CACHE_TTL_SECONDS` 为 1—3600；仅进程内保存，最多 200 条，不落地到业务数据库。缓存按城市、车辆、摆渡选择隔离，改变计时假设时重新计算，并显示原查询时间和缓存状态。
- 所有供应商 URL 由后端固定；不接收用户指定代理 URL。错误信息不会带出供应商请求 URL、密钥或原始响应。

自动化验收覆盖计时边界、单位和坐标转换、权限缺失、路线失败、限行警告、摆渡拒绝与拆分、缓存隔离、超时、登录保护及界面流程。付费接口在取得用户 Key 并开通权限后，还需以真实国内、美国、欧洲线路完成联调；模拟响应通过不能替代实时联调。
